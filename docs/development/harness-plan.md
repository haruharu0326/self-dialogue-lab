## 自動レビュー実行器の仕様

`python scripts/review.py` でHEADから現在の作業ツリーまでの変更（ステージ済み・未ステージ・未追跡）をレビューします。`--base <commit>` で比較元を変更でき、`--paths <path> ...` で変更ファイルの一部に限定できます。既存変更も対象になるため、開始時の比較元と対象一覧を保存します。リネームは削除と追加として扱います。

既定では一括検証を実行し、その構造化結果、関連コード、AGENTS.md、製品仕様、対象差分をCodex CLIへ標準入力で渡します。レビューは単発で、修正・コミット・マージは行いません。CLIの既存ログインを使い、追加のAPIキーをアプリへ保存しません。コードと文書はCodexの設定されたモデル提供先へ送信されます。ユーザー設定のモデルを使い、`--model`で明示指定もできます。

送信対象はGitが列挙したコード・仕様文書の許可パスと拡張子に限定し、DB・.env・秘密ファイル・個人データ用ディレクトリ・サンプルデータ・生成物・リンクは除外します。コードや文書へ直接書かれた秘密の自動検知を保証するものではありません。比較元も同じ規則を適用します。入力はUTF-8合計800KBまでとし、超過時に黙って省略せず失敗します。レビューは保存したスナップショットについて行い、終了時に対象・関連コード・比較元が変わっていたら結果を古いものとして扱います。

Codexは一時ディレクトリでread-only、承認要求なし、ephemeralとして実行します。作業リポジトリへ移動するよう指示せず、入力だけを読むよう依頼します。read-onlyは書込み制限であり、ホスト全体の読取り隔離を保証しません。ユーザー設定はモデル選択等のため引き継ぎます。レビュー上限は既定600秒で`--timeout`で変更可能。CLI未導入、認証・通信失敗、タイムアウト、空・不正な応答はレビュー失敗とし、「指摘なし」へ変換しません。

結果はGit対象外の`.review-runs/<実行ID>/`へinput.json、verification.json、review.json、report.json、report.mdとして保存します。指摘には重要度、対象ファイル・行、発生条件、影響、仕様根拠、確認方法を要求し、構造と対象ファイル・行の範囲を検証します。規約の矛盾はblockersへ分け、既知のモック/Geminiの不整合を勝手に解決しません。指摘の正しさは人が確認します。

終了コードは実行失敗・検証失敗が1、指摘あり・blockersあり・スキップ・未検証・対象変更なし・実行中の変更が2、指摘なし・blockersなし・全検証成功・入力不変が0です。0も人による採用判断を置き換えません。`--skip-verify`は未検証と明示し、終了コード0にしません。`--prepare-only`はモデル呼出し・検証を行わず入力と未実行レポートだけを保存します。定期実行・CI連携・自動修正ループは後続の範囲です。

CLI仕様の根拠：[公式の非対話実行](https://learn.chatgpt.com/docs/non-interactive-mode)、[CLIリファレンス](https://learn.chatgpt.com/docs/cli/reference)。ローカルのcodex-cli 0.164.0でもフラグを確認しました。

Windows PowerShellでの使用例：

```powershell
codex.cmd login
python scripts/review.py --prepare-only
python scripts/review.py
# 対象を限定する場合
python scripts/review.py --paths scripts/review.py tests/test_review.py
```

モデル呼出し前に`codex login status`でログインを確認し、未ログインならネットワーク再試行を始めず失敗として記録します。read-onlyの起動にはCLI環境側のサンドボックス設定も必要です。

## 一括検証の実行仕様

`python scripts/verify.py` を任意の作業ディレクトリから実行します。リポジトリを基準にpytest、Vitest、型チェックを含むViteビルド、一時DBでの実サーバー起動を順に確認します。失敗しても他の工程を続けますが、ビルド失敗時の起動確認は未実行とし、古いビルドを検証しません。依存の自動インストールは行いません。

pytestのJUnit XMLとVitestのJSONから件数を集計し、レポートが欠落・不正、またはテスト件数が0なら失敗とします。終了コードは失敗・必須工程未実行が1、失敗なしでスキップがある場合が2、全工程成功かつスキップなしが0です。`--allow-skips` はスキップを表示したまま終了コード2だけを0に変更します。テスト結果を完全成功と表示するためのオプションではありません。

サーバーは127.0.0.1の空きポートで起動し、health、空の初期状態、ビルド済みページを確認します。個人DBのパス、ホスト、ポートを上書きし、起動プロセスからAPIキー・任意モデル設定を除外します。HTTPプロキシを経由せず、送信APIは呼びません。起動待ちは20秒を上限とし、成功・失敗時とも自身が起動したプロセスを停止します。テスト用レポートとDBはGit対象外の一時ディレクトリに置き、終了時に破棄します。結果概要は標準出力へ表示します。

この検証は製品仕様の矛盾を解消せず、実ブラウザ操作・実モデル・実API・Dockerの確認も含みません。

## 目的と範囲

このアプリを変更するエージェントが、仕様確認、変更、検証、差分レビュー、修正を再現可能な手順で進められる開発環境を作ります。利用者向けのコードレビュー機能は追加しません。製品の実LLM/API・クラウド・マルチエージェントの対象範囲を変更する提案でもありません。

開発方針は[AGENTS.md](../../AGENTS.md)、製品仕様とFR/NFR/AT対応の入口は[文書一覧](../README.md)です。本書は開発手順の担当文書とし、製品要件の詳細を転記しません。

## 最初に解決する仕様の不整合

AGENTS.mdは全画面のモック・固定応答表示と実LLM/APIの初版対象外を指示しています。一方、README、要件定義書、api.pyはGeminiによる実対話を現在仕様として扱っています。今回の調査ではどちらも書き換えていません。自動レビューが一方を暗黙に正本として実装を戻すことは避け、衝突を報告し、製品として採用する方針をユーザーと確定してから規約・関連文書を揃えます。確定までの作業は現在のAGENTS.mdに従います。

## 導入する最小の流れ（提案）

1. 作業開始時のHEAD、ステージ済み・未ステージ・未追跡ファイルの一覧を記録する。既存変更がある場合は内容の比較基準も保持し、レビュー対象を明示する。個人データや秘密情報は収集しない。
2. 変更に関連するFR/NFR/ATと担当文書を特定する。仕様変更なら文書初稿を先に更新する。規約の矛盾は明示して扱う。
3. 実装後、Python・画面テストと画面ビルドを実行する。一時DB・ローカルポートで起動、health・ページ応答、停止を確認する。実APIや個人DBを検証に使わない。
4. 対象差分と周辺コード、関連仕様、実行結果を読み、バグ・仕様違反・検証の抜けをレビューする。テスト成功だけで仕様整合を断定しない。
5. 指摘を修正し、影響する検証を再実行する。対象差分が変わればレビューも更新する。修正ループには回数上限を設け、未解決事項は人へ返す。
6. 対象、変更点、実行結果、スキップ、未確認、未解決の指摘を報告し、人が採用を判断する。自動コミット・マージ・外部送信はこの最小構成に含めない。

上記3はscripts/verify.py、上記4はscripts/review.pyで実装しました。各工程の終了コードと成功・失敗・スキップをまとめ、必須工程の失敗時は全体も失敗にします。依存不足で未実行の場合も成功とは扱いません。起動契機の自動化・自動修正・反復回数の設定は後続の設計事項です。

## レビュー報告の形式（提案）

各指摘には、重要度、ファイルと行、発生条件、影響、仕様の根拠、再現または検証方法を含めます。根拠のない推測や好みは不具合と区別します。未実行の確認と不整合は指摘件数とは別に記録し、「指摘なし」を合格の根拠にしません。

重点観点は、承認の原子性・二重処理、未承認・拒否候補の参照除外、旧記録・削除済み記録の除外、会話と記録の削除範囲、架空サンプルの分離、秘密・個人データの扱い、Responder境界です。規則の詳細はAGENTS.mdと各担当仕様を参照します。
