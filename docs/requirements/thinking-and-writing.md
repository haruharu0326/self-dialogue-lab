# 将来要件：思考を深める対話と文書化

## 位置付け

**状態：将来要件の初稿。未実装。** 2026-10-25に、思考を深めるアプリとしての方向性と、将来のnote向け文書化に備える要件を追加しました。現行機能は[機能要件書](functional-requirements.md)を正本とします。本書は現在の画面・保存・送信の挙動を変更しません。

将来機能はFFR、将来の品質要件はFNFR、将来の受入案はFATの別番号で管理します。既存FR/NFR/ATを再利用せず、実装に着手するときに現行仕様の番号との対応を定め、設計と受入テストを更新します。

2026-10-29にユーザーが確定した方針は[方針決定](#方針決定2026-10-29)に集約します。これらも未実装であり、実装前の文書初稿です。

## 目的と成果

利用者が話す・書くことで、何を考えているか、その理由・前提・経験・迷いを言葉にし、別の見方も検討できることを目的とします。AIが結論を与えることや記事を量産することを成功条件にはしません。

成果は、本人が「考えの理由が明確になった」「前提に気付いた」「別の見方を検討できた」「次に考える問いを持てた」と振り返れることです。記事化するときは、本人の経験と判断、AIの提案、外部の事実を区別できる文章を作れることを目指します。トーン3分類や会話の長さから、思考の深さ・人格・理解力を採点しません。

## 想定する流れ

1. 深めたいテーマや、まだ言葉になっていない違和感を話す。記事を書く予定がなくても始められる。
2. 対話で理由・前提・具体例・別の見方を検討する。問いを飛ばす・立ち止まる・反論することができる。
3. 節目で理解の仮まとめを確認し、現在の考え・まだ迷う点・次の問いを本人が修正する。
4. 希望したときだけ、文章化に使う素材と読者・目的・伝えたいことを選ぶ。
5. 構成案、下書きの順に確認・編集する。記事化をやめて対話に戻ることもできる。
6. 公開してよい内容を本人が確認し、noteへ手動で転記できる文章を取り出す。アプリは投稿しない。

仮まとめや記事素材への確認は、長期記憶への保存承認や外部への送信確認とは別の操作として扱います。

## 将来の機能要件

### FFR-001 テーマと問いを保つ

- 本人がテーマ・考えたい問いを設定、修正、保留できる。テーマ名を入力しなくても対話を始められる。
- 論点が分かれたときは、元の問いと派生した問いを区別して示し、どれを続けるか本人が選べる。
- 保留した問いを後で再開できる。再開時は当時の考えを現在の立場とみなさず、今も同じか確認する。
- 保存単位や画面構成は未決。すべての会話でフォーム記入や分類を必須にしない（FAT-001）。

### FFR-002 理由と前提を掘り下げる

- 本人の発言に沿って、理由・前提・言葉の意味・具体的な経験や例を尋ねる。
- 一度に問いを詰め込まず、原則として次に考える中心の問いを1つ提示する。理由が必要な場合は、何を明確にする問いか短く示す。
- すでに答えた内容を踏まえ、同じ質問の反復を避ける。本人が答えない、質問を変える、考える時間を取る選択を尊重する。
- 感情や動機を断定せず、必要なら仮説として確認する。固定の質問一覧を順に消化しただけで「思考が深まった」と扱わない（FAT-002）。

### FFR-003 別の見方と反例を検討する

- 別の解釈、成り立たない条件、反例、選択肢の利点・欠点を検討できるようにする。
- 同意・異論のどちらにも理由を添える。毎回の反論や本人の説得を目的にしない。
- AIが出した仮の例・仮説はそのように表示し、本人の実体験や確認された事実に置き換えない。本人が提案を退けても結論や記憶に混入させない（FAT-003）。

### FFR-004 現在の考えと未決の点を振り返る

- 本人が希望する節目で「今の考え」「理由・経験」「前提」「別の見方」「未決の点・次の問い」の仮まとめを提案する。空欄をAIの推測で埋めない。
- 本人が修正・却下・保留できる。確認する前に長期記憶や現在の信念へ追加しない。
- 誤入力の修正と考えの変化を区別し、変化を採用する場合は以前の立場と現在の立場を明示する。過去・削除済みの記録を現在の根拠に使わない。
- 記事のために無理に結論へ収束させず、未決のまま終えられる（FAT-004）。

### FFR-005 文章化する素材を本人が選ぶ

- 本人が文章化を開始し、対象テーマ、読者、目的、伝えたいこと、使用する素材を確認する。対話の全履歴や長期記憶を自動的に記事素材へ取り込まない。
- 未承認・拒否候補やAIの解釈を、本人の確定した意見として参照しない。会話から使いたい箇所は本人が明示選択し、記事素材としての利用を確認する。これは長期記憶への承認とは別であり、拒否した記憶候補を自動復活させない。
- 現在の意見を書く素材は現在有効な本人確認済みの内容だけを使う。過去の考えを変化の経緯として使う場合は、本人が選択し、当時の立場と明示する。
- 各素材に原文・発言者・日時・確認状態を結び付け、AI提案と本人の言葉を区別する。素材確認後の原文変更は、再利用前に確認し直す。由来する会話が削除された素材は派生物として一緒に削除される（FFR-008）。
- 他人の名前や個人的な情報、公開したくない話を取り除いてから下書き生成へ進める（FAT-005）。

### FFR-006 構成案と下書きを作る

- 確認済み素材を使い、タイトル候補・見出し・論点の順序を含む構成案を提案し、本人の確認・編集後に本文を作る。
- 本人が伝えたいことや文体を保ち、経験・引用・結論・数字・出典を創作しない。材料が不足する部分は質問または「確認が必要な箇所」として示す。
- 未決の点や留保を、読みやすさのために断定へ変えない。重要な主張から使用素材を確認できるようにする。
- AIによる変更箇所を確認でき、部分的な採用・修正・却下ができる。生成や却下だけで本人の記憶を更新しない（FAT-006）。

### FFR-007 公開前に確認して文章を取り出す

- noteへ手動転記できる本文をプレビューし、対象の下書きと取り出す範囲を本人が確認する。出力形式はMarkdownとプレーンテキストで、確定済み（OD-008）。
- 下書き本文、内部の対話・素材情報、未公開メモ、秘密情報を区別し、内部情報を本文や添付へ自動的に含めない。本人が本文に入れた情報も公開前に見直せるようにする。
- 取り出しは**クリップボードへのコピーのみ**（Markdown／プレーンテキストから本人が選ぶ）。ファイル書き出しはしない（[方針決定4](#4-取り出しはクリップボードへのコピーのみ)）。
- 本人が経験・事実・引用元・個人情報・結論を確認できる。アプリが事実確認や匿名化を完全に保証したとは表示しない。
- この段階ではnoteのアカウント認証、直接投稿、公開予約、公開済み記事との同期を行わない（FAT-007）。

### FFR-008 思考と文章の変化を本人が追える

- 採用した仮まとめ・構成案・下書きの版を区別し、いつ何を変更したか確認できる。保存操作・版の粒度・復元方法は設計時に確定する。
- 対話、長期記憶、記事素材、下書き、コピーした文章を別のものとして扱い、それぞれの削除範囲を説明する。
- 会話を削除すると、その会話に由来する派生物（テーマ・問い、仮まとめ、記事素材、構成案・下書きとその版）も一緒に削除する。長期記憶の承認済み記録は会話削除で消さない（[方針決定2](#2-会話削除は派生物も削除する)）。削除済みの会話・素材を以後の生成へ再利用しない。
- クリップボードへコピー済みの文章や、本人がアプリ外へ貼った文章は消えたとは扱わない（FAT-008）。

## 将来の非機能要件

|ID|要件|
|---|---|
|FNFR-001 本人の主体性|AIの仮まとめ・解釈・反論・本文を本人が確認、修正、却下できる。未決・保留も成果として扱い、結論の確定や公開を促し続けない|
|FNFR-002 根拠と時点|本人の原文、AI提案、外部資料、未確認の事実を区別し、素材との対応と当時の立場を追える。要約を原文と偽らず、原文を要約で上書きしない|
|FNFR-003 個人情報と送信|ローカル保存を基本とし、下書き生成など新しい外部送信の目的・対象・範囲を本人が確認する。現行の対話送信への同意だけで記事素材の一括送信や公開まで同意済みとしない。問いの文・仮まとめ・記事素材・下書きのGeminiへの送信は、操作ごとに送る内容を示して確認する（[方針決定3](#3-新しい外部送信は操作ごとに確認する)）。文書・書き出し・個人データをGitへ追加しない|
|FNFR-004 保存と削除の整合性|確認済み素材とその版が混ざらず、失敗時に原文や採用済み下書きを壊さない。削除済み素材の新規参照を防ぎ、会話削除で派生物も削除されること、コピー済みの文章は消えないことを説明する|
|FNFR-005 分かりやすさと評価|基本は対話を中心とし、文章化は本人が希望したときだけ開く。構造・境界の自動テストと、本人による思考深化・文章の納得感の評価を分ける。モデルや代替応答器のテスト成功を、実対話品質の保証と呼ばない|

現行の[NFR](non-functional-requirements.md)は維持します。将来の外部送信・文書保存・書き出しを実装するときに、送信確認と削除範囲の仕様を更新します。

## 方針決定（2026-10-29）

ユーザーが確定した方針です。すべて**未実装**で、実装時に各担当文書を更新します。応答器の二重モードそのものは[FR-028](functional-requirements.md#fr-028-応答モードを選ぶ未実装)に定義します。

### 1. 応答モードと本書の機能の関係

応答器は「固定応答（モック、既定）」と「Gemini（本人が明示的に有効化したときだけ）」の二重モードです。モードの変更は本人の明示操作のみで、失敗時に自動で切り替えません。固定応答モードでは外部送信をしません。

### 2. 会話削除は派生物も削除する

- 会話を削除すると、その会話に由来するテーマ・問い（FFR-001）、仮まとめ（FFR-004）、記事素材（FFR-005）、構成案・下書きとその版（FFR-006,008）も一緒に削除する。
- 削除前の確認画面で、**消えるもの**（会話、上記の派生物）と**残るもの**（長期記憶の承認済み記録、クリップボードへコピー済みの文章など、現行どおり残すもの）を説明する。
- 現行の「会話削除と記録削除を分ける」は維持する。長期記録は会話削除で消えない。長期記録の削除（忘れる）と、それを根拠にした派生物の関係は未決（OD-007）。
- 現行の[FR-022](functional-requirements.md#fr-022-会話履歴を消す)・[NFR-010](non-functional-requirements.md#nfr-010-削除範囲)は、各FFRの実装時に削除対象を追加する形で更新する。

### 3. 新しい外部送信は操作ごとに確認する

問いの文・仮まとめ・記事素材・下書きをGeminiへ送る新しい送信は、現行の対話送信の同意（[FR-023](functional-requirements.md#fr-023-接続と送信を確認する)）とは別に、**操作ごとに送る内容を示して本人が確認する**（FNFR-003）。確認前は送信しない。固定応答モードではそもそも送信しない。

### 4. 取り出しはクリップボードへのコピーのみ

FFR-007は、本人が確認した下書き本文をMarkdownまたはプレーンテキストでクリップボードへコピーすることに限る。ファイル書き出し、自動要約は提供しない。通常画面の「エクスポートや会話要約を提供しない」という現行制限は、「本人が開始し本人が確認する仮まとめ（FFR-004）とクリップボードへのコピー（FFR-007）に限り許可」へ、該当FFRの実装時に更新する予定である。

### 5. 実装順と番号の対応方針

実装順は次のとおり。A2（Responder契約）→A1（送信排他）は[harness-plan](../development/harness-plan.md#次回対応への引き継ぎ2026-10-25-mainレビュー)の引き継ぎ項目で別ブランチで作業中。

1. responder-mode（FR-028、ブランチ想定`feature/responder-mode`）
2. FFR-001 → 002 → 003 → 004 → 005 → 006 → 008 → 007

番号は、新しい機能要件をFR-028以降、受入テストをAT-048以降の連番で、実装ブランチごとに採番する。FFRの1項目に対し、1つ以上のFR・ATを割り当て、[docs/README.mdの将来要件との対応表](../README.md#将来要件との対応未実装)に記録する。具体的な番号の割当ては各実装ブランチで確定する（現時点の予約はFR-028とAT-048＝応答モードのみ）。FFR/FAT番号は将来用として残し、FR/ATへ番号を移しても旧番号を別機能へ再利用しない。

### 6. 固定応答モードでのFFR-002/003/004/006

固定応答モードは入力の内容を理解せず、AIが理解・生成したように見せない。「入力の内容は理解していません」等を画面に明示する。

|FFR|固定応答モードで行うこと（上限）|Gemini有効時のみ行うこと|
|---|---|---|
|FFR-002|本人が型を選び、定型の問い・視点を示す|発言に沿った問い|
|FFR-003|本人が型を選び、定型の視点を示す|発言に沿った別の見方・反例|
|FFR-004|本人が自分の発言を選んで仮まとめの枠に貼る|仮まとめの生成|
|FFR-006|本人が自分の発言を選んで構成案・下書きの枠に貼る|構成案・本文の生成|

どちらのモードでも、自動テストの成功を対話品質・思考深化の検証とは表現しない（FNFR-005）。

## 未決事項

- **OD-007**（一部決定）：会話削除時の派生物の扱いは**決定済み**（[方針決定2](#2-会話削除は派生物も削除する)）。未決は、テーマと問いの保持単位、仮まとめを採用・保存する操作、記事素材の確認と長期記憶承認の区別、版の粒度、長期記録を忘れたときの派生物の扱い、保持期間。
- **OD-008**（一部決定）：出力形式は**決定済み**（クリップボードへのコピー、Markdown／プレーンテキスト。[方針決定4](#4-取り出しはクリップボードへのコピーのみ)）。未決は、出典・原文対応の表示、公開前確認の項目、想定する文章の種類・長さ・文体、本人による思考深化の評価方法。noteへの直接連携を検討するかは将来の別判断とする。
- 外部資料の検索・事実確認をアプリで支援するか、モデルへ渡す素材量をどう制限するかは別途定める。本人が貼ったURLやAIの出力だけをもって事実確認済みとしない。

将来の受入案と未実施状態は[受入テスト仕様書](../testing/acceptance-tests.md#思考深化と文書化の将来受入案)を正本とします。
