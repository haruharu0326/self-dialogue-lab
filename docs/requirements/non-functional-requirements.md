# 非機能要件書

対象は通常の1画面チャットです。要件、確認方法、適用範囲を記載し、実施結果は[受入テスト](../testing/acceptance-tests.md)へ集約します。

将来の思考深化・文書化に必要な本人の主体性、出典、外部送信、文書保存・削除の要件は[将来要件FNFR-001〜005](thinking-and-writing.md#将来の非機能要件)へ集約しています。実装時に本書の現行制約との変更点を明示します。

## NFR-001 実行環境

要件：Windows 10/11とDocker DesktopのLinuxコンテナを主に想定。DockerはPython 3.12と画面ビルド用のNode.js 24、直接起動はPython 3.11以上とNode.js 24以上（画面のビルドのみ）。開発テスト環境はWindows / Python 3.13.7。macOS/Linuxホストと実ブラウザは未確認。確認方法：依存導入、起動、AT-040。適用範囲：実行環境。版番号だけを根拠に動作保証しない。

## NFR-002 単一ユーザー・ローカル

要件：1人用、ホストの127.0.0.1:8501だけへ公開。コンテナ内の待受0.0.0.0はホストの全インターフェース公開を意味しない。APIはHostが127.0.0.1またはlocalhostの要求だけを受け、別サイトのOriginからの更新操作を拒否する（DNSリバインディング・クロスサイト操作の防止）。認証・複数利用者・クラウド公開は対象外。確認方法：Compose設定と起動状態、tests/test_api.py。適用範囲：アプリの公開先。

## NFR-003 性能

暫定目標：会話100往復・記憶100件で、ローカル保存・描画は通常1秒以内。APIの待ち時間、依存導入、初回起動を除く。測定結果：未測定で保証値ではない。APIのソケット待ち時間は設定可能（既定120秒）で、処理全体や応答性能の保証ではない。確認方法：同一環境で10回測り中央値・最大値を記録（AT-041）。適用範囲：通常の保存と描画。OD-002：入力上限・件数上限・ページング・性能基準の確定は未決。

## NFR-004 永続性

要件：正常にコミットした会話・記憶・候補は再接続・再起動後も残る。Dockerは名前付きボリュームを使用。通常のdownやコンテナ再作成で消さない。確認方法：別プロセスからの再取得、コンテナ再作成（AT-033,042）。適用範囲：SQLite業務データ。ストレージ障害・停電・ボリューム明示削除からの保護は保証しない。

## NFR-005 更新の整合性

要件：会話の発言・返答・候補、承認の記録追加・状態変更、会話削除を各トランザクションで一括更新。同じ候補の再承認・再拒否を拒否。recordsのIDを削除後に再利用しない。確認方法：二重操作と障害注入（AT-033,039）。適用範囲：単一ユーザーの保存。多数同時アクセスは保証対象外。

## NFR-006 エラーと復旧

要件：入力不備と想定内の接続・DB障害を安全なメッセージで通知。APIを自動再試行せず、固定応答へ切り替えない。未完了のDB更新はロールバックし、設定・通信・保存先の修正後に手動再試行する。確認方法：異常系テスト（AT-039）。適用範囲：想定内の業務エラー。自動修復やバックアップは未実装。

## NFR-007 個人情報とGit

要件：.env、DB本体・journal/WAL、個人書き出し、モデル、仮想環境、テストデータをGitとビルド入力から除く。.env.exampleは空の見本だけを追跡する。キーのあるファイルを見本として扱わない。確認方法：git check-ignore、追跡一覧、.dockerignore（AT-038）。適用範囲：リポジトリとDockerビルド。任意の名前で別場所へ保存した機微ファイルの自動検出は行わない。

## NFR-008 外部への送信

要件：送信確認後、Geminiへ今回の発言・直近10往復・現在有効な記憶を送る。キーはサーバー側HTTPヘッダーだけへ載せ、URLや本文へ出さない。候補一覧、評価、画像は送らない。過去の会話文脈と長期記憶を区別する。画面は外部の画像・フォント・スクリプト・利用統計を読み込まない（ビルド済みの静的ファイルと同梱の風景画像だけを同じサーバーから配信）。確認方法：代替通信の入力検査と設定レビュー（AT-034,037,038）。適用範囲：通常製品。Google側の保存・利用枠・料金は外部条件に従い、ローカル削除で相手側も削除されるとは保証しない。

任意分析の外部送信境界：モデルの事前取得だけHugging Faceへ接続し、取得処理は本人の会話を読みません。分析時はローカルファイルだけを使用し、結果は外部送信・永続化しません（FR-025 / AT-045）。原文の既存Gemini送信範囲は変えません。

音声入力の外部送信境界：モデル取得だけHugging Faceへ接続します。録音はブラウザから同じPCのAPIサーバーへ渡し、ローカルモデルで処理。録音や未送信の下書きは外部APIへ送りません。確認して送信した文章には既存のGemini送信規則を適用します（FR-026 / AT-046）。

## NFR-009 ログ

要件：業務ログファイルを作らず、発言・記憶・候補・キー・API生エラーを標準出力へ記録しない。APIサーバーのアクセスログは無効にする。SQLiteへの意図した業務保存はログではない。基盤の起動通知等と業務ログを区別する。確認方法：異常系の出力検査とソース確認（AT-039）。適用範囲：アプリが制御する通知。未知のバグのフレームワーク出力まで完全な秘匿を保証しない。

## NFR-010 削除範囲

要件：記憶を忘れる操作と会話削除を分け、範囲と取り消せないことを画面で説明。過去の引用は元の記憶の削除で自動消去しない。確認方法：対象外テーブル・写しの保持を検査（AT-035,036）。適用範囲：本人用DB。バックアップやDBの空きページを含む完全消去は対象外。通常UIにはエクスポートを置かない。

## NFR-011 シンプルさと表示

要件：通常UIは対話1画面。「話す→覚える→次回参照」を中心にする。ナビ、シナリオ、評価フォームを表示しない。画面幅960px以下ではサイドバーを「記憶と設定」のメニューへ畳む。任意の文章トーン分析は本人発言の折りたたみに置く（[FR-025](functional-requirements.md#fr-025-文章のトーンを分析する)）。本人の発言と推測を含むGemini返答を分ける。見た目は罫線の帳面とし、背景画像・外部フォントを使わない（[見た目の方針](../design/external-design.md#見た目の方針)）。動く背景や自動再生は使わない。確認方法：画面テスト（Vitest）とPC・モバイル目視（AT-032,043,045）。動きは考え中の表示、録音中の点滅、承認時の「覚えた」印の1回に限り、prefers-reduced-motionで止める。アクセシビリティ・コントラストの正式監査は未実施。

## NFR-012 責務分離とテスト

要件：画面（React）、HTTP API、業務手順、DB、Geminiアダプターを分離。DBとアダプターの境界をブラウザや実APIなしで、画面をサーバーなしで検証可能にする。確認方法：テスト実行とimport依存の確認（AT-032〜039）。適用範囲：通常機能と共通部。代替通信の成功を実モデルの品質評価と呼ばない。

## NFR-013 交換可能性

要件：業務処理へ応答器を注入でき、API通信をテスト用に置換できる。別モデルへ交換しても未承認の長期保存禁止と出典ID検証を維持する。確認方法：代替応答器・通信による境界テスト（AT-032〜034,039）。適用範囲：内部契約。他社APIの実装は対象外。

## 未決事項

OD-003：暗号化、バックアップ・復元、監査ログ方針は未決。現状は認証・暗号化・業務ログなし。実接続・目視・性能・他OS等の未確認状況は[受入テストの実施記録](../testing/acceptance-tests.md#実施記録)を参照してください。
