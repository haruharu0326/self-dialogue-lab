# 要件定義書

## 背景と目的

考えを記録する管理ツールを広げるのではなく、**話して自分の考えを整理し、自分の回答を覚えて次の対話へ活かす**ことを目的にします。通常画面は1つのチャットです。機能数の多さより、何をするアプリなのかが分かることを優先します。

Geminiが質問や別の視点を返し、本人が必要だと判断した回答だけを記憶します。常に同意する相手、毎回反論する相手、人格や意識を再現した相手を目指しません。

将来は、**対話を通じて自分の思考を深め、本人が納得した内容を自分の言葉で文章にする**ことまで支援します。note向けの記事化を想定しますが、問いが深まることや未決の点が明らかになることも成果とし、毎回の記事化や結論の確定を求めません。将来要件の正本は[思考を深める対話と文書化](thinking-and-writing.md)です。今回追加するのは要件であり、画面・応答器・DB・外部サービス連携の実装は含みません。

## 対象ユーザーと解決する課題

自分のPCで1人で利用する人。考えがまとまらない、過去に話したことが次の相談に活きない、AIの推測が本人の信念として保存される、といった問題を扱います。多数の画面や分析結果を操作しなくても、会話を続けられる形にします。

## 利用シナリオ

1. 接続を設定し、会話と覚えた回答をGoogleへ送ることを確認する。
2. 迷っていることや考えていることを話す。
3. 返答を読み、必要ならそのままチャットで訂正・補足する。
4. 残したい自分の回答で「この回答を覚えておく」を開き、内容を確認して保存する。
5. 次の対話で、その回答を参考にした返答を受ける。
6. 不要な記憶は忘れさせる。会話履歴の削除は別に行う。
7. 必要な発言だけ「文章のトーン（任意）」を開いて分析する。結果は本人の気持ちの断定として扱わない。

## 用語

|用語|定義|
|---|---|
|回答／本人の発言|ユーザーが入力したテキスト。AIの返答とは別|
|会話文脈|直近10往復のGemini会話。未承認の元発言も含み得る短期的な文脈|
|保存候補|本人の入力原文を機械的に複製したpendingの候補。まだ記憶ではない|
|覚えた回答／記憶／長期記録|本人が内容を確認し「覚えておく」で保存したrecordsの行|
|学習|覚えた回答を次回のAPI入力で参照すること。モデル重みの更新ではない|
|現在有効な記憶|superseded=0で、削除されていない記録|
|参照の写し|返答時に実際に使った記録の内容を保持するコピー|
|推測|Geminiが生成した解釈や提案。本人の発言・検証された事実とは限らない|

## 対象範囲

音声入力を任意機能として追加します。録音をローカルで文字起こしし、確認した文章だけを既存の対話へ送ります。録音自体は保存・外部送信しません。初版の対象外だった音声を今回の拡張で追加し、読み上げ・連続認識・外部音声APIは将来の対象として残します。詳細は[FR-026](functional-requirements.md#fr-026-音声から入力する)を参照。

任意の文章トーン分析を通常画面に追加します。機能の入出力・保存境界は[FR-025](functional-requirements.md#fr-025-文章のトーンを分析する)、モデルと配置は[内部設計](../design/internal-design.md#通常画面の文章トーン分析)を正本とします。

Python（FastAPI）/ React（Vite・TypeScript）/ SQLite / pytest・Vitestによるローカル単一ユーザーのアプリ。画面はReact、業務処理・DB・応答器はPythonのAPIサーバーに置き、同じ127.0.0.1:8501で配信します。2026-10-25に通常画面をStreamlitから移行しました（検証用のsrc/lab.pyはStreamlitのまま）。Geminiとのテキスト対話、回答の確認保存・拒否、記憶の閲覧・削除、会話履歴、送信範囲と設定の案内、自然風景の背景を提供します。機能詳細は[機能要件書](functional-requirements.md)に集約します。

通常入口は `src/app.py`。本人用DBだけを使い、架空サンプルを自動投入しません。旧データは削除しません。従来の管理・シナリオ・分析機能は `src/lab.py` の検証用に分離し、通常製品の必須操作には含めません。

通常画面の保存前の内容編集は可能です。保存後の編集、旧記録と新記録を関連付ける変化管理、エクスポートは通常画面に提供していません。必要なら古い記憶を忘れさせ、新しい回答を確認保存できますが、両者の自動関連付けは行いません（OD-005）。

## 対象外

ファインチューニング、重み更新、自動的な人格・価値観の推定と保存、意味検索、会話の自動要約、マルチエージェント、音声読み上げ・連続認識・外部音声API、ベクトルDB、クラウド公開、既存個人データの自動取り込み、Gemini以外の実API（Geminiは本人が有効化したときだけ使う。[FR-028](functional-requirements.md#fr-028-応答モードを選ぶ未実装)）。評価・シナリオ・JSON出力も通常画面の対象外です。任意の文章トーン3分類は通常画面で提供します（[FR-025](functional-requirements.md#fr-025-文章のトーンを分析する)）。

## 前提条件と制約

Geminiのキーを利用者が発行し、実行環境に設定します。`.env.example` は空の見本、`.env` は実際のローカル設定です。Docker Composeは.envを読み込みますが、Python直接起動では環境変数の設定が必要です。接続設定の詳細は[README](../../README.md)と[内部設計](../design/internal-design.md#設定と起動)に集約します。

ネット接続とGoogle側の利用権限・枠が必要です。料金や無料利用を保証しません。APIを設定したことと、実際に疎通できたことは別です。認証・DB暗号化はなく、PCの利用者間の隔離はOSに依存します。

## AIの振る舞い方針

次をGeminiへの指示に含めます。指示があることと品質保証は区別します。

- 同意・反論に理由を添え、毎回の反論を目的にしない。
- 本人の発言、AIの推測、外部の事実を区別する。
- 過去の発言から現在の人格を断定しない。
- 一時的な感情・仮の意見を自動で信念として保存しない。
- 文脈を確認せず違いを矛盾と決めつけない。
- 参照していない記録を根拠にしない。
- 人間の内面や意識を再現したと主張しない。

## 完成条件

チャットと記憶の操作を迷わず使えること。本人の確認前に長期記憶へ入らず、確認後だけ次回の根拠に含まれ、拒否・削除・二重操作の境界が守られること。接続と実画面を確認し、文書・実装・テストの対応を追えること。未実施項目は[受入テスト仕様書](../testing/acceptance-tests.md)で未確認と記載し、完成扱いにしません。

## 将来拡張と未決事項

開発用にGemini応答の評価CLIを追加しました。通常画面の対象範囲は維持し、架空ケース・反復実行・人の採点・条件比較は[応答評価CLIの要件と設計](../development/response-evaluation.md)を正本とします。評価基盤の導入だけで対話品質を検証済みとは扱いません。

思考深化とnote向け文書化の将来範囲・要件・導入段階は[将来要件](thinking-and-writing.md)を参照してください。現行の「通常画面にエクスポートや会話要約を提供しない」という制限は実装までそのまま維持します。2026-10-29の方針で、将来は「本人が開始し本人が確認する仮まとめ（FFR-004）とクリップボードへのコピー（FFR-007）に限り許可、ファイル書き出し・自動要約は引き続き提供しない」へ更新する予定です（未実装）。noteへの直接投稿・認証連携は今回の将来要件にも含めず、本人が確認した下書きの手動転記（クリップボードへのコピー）を想定します。

応答器は、既定を固定応答（モック）、Geminiは本人が明示的に有効化したときだけ使う二重モードにする方針です（[FR-028](functional-requirements.md#fr-028-応答モードを選ぶ未実装)、今後実装・未実装）。実装までは上記のGemini対話が現行仕様です。Gemini以外の実API、クラウド、マルチエージェントは引き続き対象外です。会話削除は将来、派生物も削除する方針です（[方針決定](thinking-and-writing.md#方針決定2026-10-29)）。

OD-007：思考テーマの保持単位、過去の問いの再開、保持期間、記憶削除と派生物の関係（会話削除時の派生物の扱いは決定済み）。OD-008：出典情報の持ち方、本人確認と文章化の評価方法（クリップボードへのMarkdownコピーは決定済み。プレーンテキストは未決の提案）。詳細な未決事項は[将来要件の未決事項](thinking-and-writing.md#未決事項)へ集約します。

OD-006：日本語の文章トーン分類の体系的な精度評価と、用途に適したモデルの再選定は未決です。動作確認では直感に合わない分類もあり、本人の感情や対話品質を検証できたとは扱いません。感情の細分類、結果の履歴保存、無確認での応答反映は対象外です。本人が選択した送信時の補助利用は[FR-027](functional-requirements.md#fr-027-トーンを返答の補助情報として渡す)で扱います。

OD-001：記憶増加時の関連検索、要約、送信件数制限、対話品質の評価方法は未決。OD-005：保存済み回答の訂正・変化を通常画面でどこまで扱うかは未決です。機能を増やす前に、対話の流れを妨げないか確認します。アーキテクチャ図は今後作成予定で、今回の文書整理では追加しません。
